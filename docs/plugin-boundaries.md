# QingCharms 插件职责与构筑链路

本文记录重新定义后的目标边界。它是后续实现的设计依据，不代表当前 `0.2.0` 已经实现这些行为。

## 职责划分

| 能力 | QingCharms | ILS |
| --- | --- | --- |
| 饰品自定义槽位、装备、替换、卸下 | 负责 | 不负责 |
| 饰品实例及玩家装备数据持久化 | 负责 | 不负责 |
| 饰品定义中的构筑词条及装备词条统计 | 负责 | 不负责 |
| 构筑条件判定及效果 Lore 生成 | 负责 | 不负责 |
| 解析饰品 Lore 并应用属性到玩家 | 不负责 | 负责 |
| 玩家战斗属性与战斗结算 | 不负责 | 负责 |

玩家实际属性以 Lore 为准。QingCharms 生成构筑效果 Lore，但不在内部将解析数值直接应用给玩家。当前构筑按词条配置触发，不读取基础饰品 Lore 的属性数值；内部属性解析留待以后设计饰品升级时确定。

## 构筑计算

1. 饰品定义可配置一个或多个构筑词条，例如火焰宝石配置 `[火]`，海洋宝石配置 `[水]`。
2. 每件已装备饰品对其配置的每个词条计 1 次；同一饰品内相同词条去重。当前不允许同一个饰品 ID 重复装备。
3. 构筑定义放在独立的 `builds.yml` 中，至少包含构筑 `id`、显示名 `name`、条件 `condition` 和效果 `attribute`。
4. 每个条件包含词条 `tags`、目标数量 `count` 和比较符 `operator`。支持 `lt`、`gt`、`eq`、`gteq`、`lteq`。同一构筑的全部条件必须满足（AND）才触发。
5. 每条 `attribute` 直接写完整 Lore 行，使用 ILS 配置的属性名和可识别格式，例如 `暴击率: +30%（焱之时刻）`。
6. 多个构筑可以同时触发；各自的效果行全部进入构筑效果物品，由 ILS 按 Lore 数值相加。
7. 目前只展示当前已触发的构筑。独立构筑图鉴不在本阶段范围内。

配置示例：

```yaml
flame-moment:
  name: "焱之时刻"
  condition:
    - tags: "火"
      count: 3
      operator: gteq
  attribute:
    - "暴击率: +30%（焱之时刻）"
```

同一属性 Lore 行由多个构筑产生时，每个构筑各保留一行并分别交给 ILS 累计。`classes.yml` 的旧 `rules` 停止参与计算；其中 `classes` 仍用于职业与装备限制，旧规则内容保留供管理员迁移。

## GUI 与 ILS 桥接

- 装备 GUI 保留一个专用属性展示槽，集中展示当前触发构筑的名称和效果 Lore。
- 展示槽内容是运行时生成的效果物品，不写入基础饰品或玩家饰品存档。
- GUI 关闭时，构筑仍然生效。QingCharms 的装备快照 API 持续返回已装备饰品和该效果物品，ILS 从快照读取完整 Lore。
- 同一装备状态下，GUI 展示和 API 提供给 ILS 的构筑效果必须一致。
- 装备状态变化或构筑配置重载后重新计算并更新缓存。
- ILS 缺席时，QingCharms 仍判断构筑并显示效果；玩家属性不会因此改变。
- ILS 按冒号前文本识别属性名，完整效果 Lore 必须符合 ILS 当前支持的格式。来源说明可跟在数值后，不可破坏属性名和值的解析。

## 当前讨论范围之外

- 饰品属性升级、强化或成长如何解析和修改 Lore。
- 构筑图鉴和未触发构筑的玩家侧展示。
- QingCharms 内的战斗属性计算、玩家属性应用或战斗结算。
